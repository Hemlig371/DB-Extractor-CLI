# DB Extractor CLI

Утилита для быстрой выгрузки данных из реляционных баз данных в форматы Parquet, CSV, Arrow IPC и JSONL. Построена на базе `connectorx` (Rust) и `polars` (Apache Arrow).

> Есть две сборки с одним интерфейсом: Python (этот каталог `src-python`) и Rust (`src-rust`, потоковая запись, не держит весь результат в памяти). Описание Rust-сборки и отличий: [src-rust/README.md](src-rust/README.md).

## Поддерживаемые базы данных

Подключение задаётся URI в `--conn`. Поддерживается всё, что умеет `connectorx`:

| База данных | Пример URI |
|---|---|
| Oracle | `oracle://user:pass@host:1521/service` (TNS-алиас: `oracle://user:pass@alias?alias=true`) |
| PostgreSQL | `postgresql://user:pass@host:5432/db` |
| ClickHouse | `clickhouse://user:pass@host:port/db` |
| MySQL, MariaDB | `mysql://user:pass@host:3306/db` |
| SQL Server, Azure SQL | `mssql://user:pass@host:1433/db?encrypt=true` |
| SQLite | `sqlite://` + путь к файлу (на Windows путь нужно URL-кодировать) |
| BigQuery | `bigquery://` + путь к json-файлу ключа |
| Trino | `trino+https://user:pass@host:port/catalog` |
| Redshift | `redshift://user:pass@host:5439/db` |

Параметры подключения (SSL и т. п.) передаются в query-части URI, подробности в [документации connectorx](https://sfu-db.github.io/connector-x/databases.html). Для Oracle на машине должен быть установлен Oracle Instant Client.

Версии библиотек: `polars` 1.43.2 и новее (проверяется на 1.x и 2.x), `connectorx` 0.4.6 и новее (ClickHouse поддерживается начиная с 0.4.6).

## Синтаксис

```bash
db-extractor --conn <CONNECTION_STRING> [ОПЦИИ]
```

### Обязательные параметры:
- Строка подключения, одним из трёх способов:
  - `--conn` : строка подключения к базе данных (см. таблицу выше).
  - `--conn-file` : путь к текстовому файлу, содержащему строку подключения (BOM допускается). Пароль не виден в списке процессов. Если заданы и `--conn`, и `--conn-file`, используется файл.
  - переменная окружения `DB_EXTRACTOR_CONN`, если ни `--conn`, ни `--conn-file` не указаны.
- **ОДИН** из двух параметров для SQL-запроса:
  - `--query` : один SQL-запрос текстом прямо в консоли. Завершающий `;` допускается. Несколько запросов через `--query` не поддерживаются, для них используйте `--query-file`.
  - `--query-file` : путь к файлу `.sql` с запросами, ИЛИ путь к папке (в таком случае обработаются все `.sql` файлы внутри, включая вложенные папки, в алфавитном порядке; регистр расширения не важен). Если запросов не нашлось, утилита завершается с ошибкой.

### Опциональные параметры:
- `--out` : путь к итоговому файлу (например, `data.parquet`). Обязателен, если не указан внутри SQL-запроса через `-- @DX_OUT`. Разные запросы одного запуска не могут писать в один файл: это проверяется до обращения к БД.
- `--format` : формат вывода (`csv`, `parquet`, `arrow`, `jsonl`). По умолчанию определяется по расширению файла (`.csv`, `.parquet`, `.arrow`/`.ipc`, `.jsonl`/`.ndjson`; суффиксы `.gz`, `.zst`, `.zstd`, `.zip` при этом отбрасываются). Неизвестный формат это ошибка.
- `--compression` : алгоритм сжатия и (опционально) уровень через двоеточие: `zstd`, `zstd:10`, `gzip:6`. Регистр не важен, `gz` означает `gzip`.

  | Формат | Поддерживаемое сжатие | По умолчанию |
  |---|---|---|
  | Parquet | `zstd`, `gzip`, `snappy`, `brotli`, `lz4`, `uncompressed` | `zstd` |
  | CSV | `gzip`, `zstd` (уровень учитывается) | без сжатия |
  | Arrow IPC | `lz4`, `zstd`, `uncompressed` | без сжатия |
  | JSONL | сжатие не поддерживается | без сжатия |

  Если сжатие не задано, оно выбирается по расширению файла: `.gz` означает gzip, `.zst`/`.zstd` означает zstd. Если сжатие не поддерживается форматом, выводится предупреждение и файл записывается без сжатия. Для CSV имя файла остаётся таким, как вы его задали (например, `users.csv` с `gzip:6` даёт gzip-содержимое в файле `users.csv`). `.zip` не поддерживается.
- `--partition-on` : имя числовой колонки без NULL (обычно ID) для параллельной выгрузки (ConnectorX).
- `--partitions` : количество партиций. Работает только вместе с `--partition-on`; если задан только один из двух параметров, выводится предупреждение и выгрузка идёт без партиций.
- `--cast-universal` : приведение типов исходной БД к универсальным типам Arrow/Parquet, чтобы не делать вручную маппинг типов между базами (подробности ниже).
- `--encoding` : кодировка файлов запросов (по умолчанию `utf-8-sig`, то есть UTF-8 с необязательным BOM). Например, `--encoding cp1251`.

### Дополнительные возможности:
- `--continue-on-error` : продолжить выполнение остальных запросов при ошибке в одном из них. Утилита всё равно вернёт код ошибки (`1`) в самом конце, если были упавшие запросы. Без этого флага новые запросы после первой ошибки не запускаются (уже выполняющиеся дорабатывают).
- `--workers` : количество одновременных потоков/воркеров для скачивания нескольких таблиц (Thread Pool). По умолчанию `1`. Каждый воркер держит свой результат в памяти, а у каждого партиционированного запроса есть собственные подключения к БД.
- `-q`, `--quiet` : тихий режим. Отключает вывод в консоль, включая предупреждения (ошибки по-прежнему пишутся в `export_log.txt`).
- `--fill-nulls` : заполнить пустоты (null) значениями по умолчанию (`'null'` для строк и категорий, `0` для чисел, включая Decimal; даты и булевы не меняются). Можно указать конкретные колонки через пробел, либо оставить без значений для всех.
- `--drop-nulls` : удалить строки с пропусками. Можно указать конкретные колонки через пробел, без значений: по всем колонкам.
- `--utc` : привести столбцы даты/времени к UTC. Значения с часовым поясом пересчитываются в UTC. Значения **без** часового пояса считаются уже выраженными в UTC и просто получают эту метку (сдвига нет). Это важно для Oracle `DATE` и `TIMESTAMP`, которые приходят без пояса. Тип `Date` не затрагивается.
- `--categorize` : список столбцов для перевода в категориальный тип (Categorical). Если указан `--cast-universal`, категориальные столбцы возвращаются в строки.
- `--hash-columns` : список столбцов для хэширования (маскирование PII, например, email). По умолчанию используется SHA-256 без соли от текстового представления значения (для чисел и дат это представление polars), NULL остаётся NULL. Хеш необратим (расшифровать его нельзя), но без соли короткие или предсказуемые значения (телефоны, email) можно восстановить перебором. Чтобы этого избежать, задайте секретную соль: `--hash-salt` или переменную окружения `DB_EXTRACTOR_HASH_SALT`; тогда значения хешируются как HMAC-SHA256. Одна и та же соль даёт одинаковые хеши в разных выгрузках, поэтому по ним по-прежнему можно соединять таблицы.

Имена столбцов в `--hash-columns`, `--categorize`, `--fill-nulls`, `--drop-nulls` сопоставляются **без учёта регистра** (Oracle возвращает `EMAIL`, пишете вы `email`). Если столбец для `--hash-columns` не найден, запрос завершается ошибкой и ничего не записывается (иначе данные ушли бы в файл открытыми). Для остальных опций ненайденный столбец только пропускается с предупреждением.

### Универсальный каст (`--cast-universal`)

Приводит типы, которые читаются не везде, к простым:
- `Decimal` приводится к `Float64`. Это float двойной точности: около 15–17 **значащих** цифр всего числа, а не после запятой. Числа с большим числом цифр (например, 20-значные идентификаторы или суммы вида 123456789012.123456789) теряют точность. connectorx передаёт Decimal с фиксированным масштабом 10, поэтому знаки после десятого в любом случае не сохраняются. Если нужна точность, приведите колонку к строке в самом SQL (`CAST(col AS VARCHAR2(50))`);
- `Datetime` приводится к микросекундам (наносекунды усекаются), значения с часовым поясом пересчитываются в UTC и становятся значениями без пояса;
- `Categorical`, `Object`, `Unknown`, `Int128` приводятся к строкам.

Остальные типы остаются как есть.

## Продвинутые возможности

### 1. Выполнение нескольких запросов (разделение по `;`)
Если вы используете `--query-file`, можно указать несколько независимых SQL-запросов, разделив их точкой с запятой (`;`). Утилита выполнит их по очереди, очищая память между запусками. `;` внутри строк (`'...'`, `"..."`, `` `...` ``), PostgreSQL-литералов (`$$...$$`, `$tag$...$tag$`), Oracle `q'[...]'` и комментариев разделителем не считается. Фрагменты без SQL (например, комментарий в конце файла) пропускаются. PL/SQL-блоки и пакетные команды вроде T-SQL `GO` не поддерживаются.

### 2. Настройки прямо в SQL-комментариях
Чтобы гибко управлять каждым запросом при пакетной выгрузке, можно использовать специальные аннотации в SQL-комментариях:

```sql
-- @DX_OUT: reports_2023.parquet
-- @DX_PARTITION_ON: report_id
-- @DX_PARTITIONS: 4
-- @DX_COMPRESSION: zstd:10
-- @DX_CATEGORIZE: status, type
-- @DX_FILL_NULLS: status, category
SELECT * FROM reports WHERE year = 2023;

-- @DX_OUT: users_active.csv
-- @DX_COMPRESSION: gzip:6
-- @DX_HASH_COLUMNS: email, phone
-- @DX_UTC
SELECT * FROM users WHERE active = true;
```
Доступные аннотации: `@DX_OUT`, `@DX_FORMAT`, `@DX_COMPRESSION`, `@DX_PARTITION_ON`, `@DX_PARTITIONS`, `@DX_FILL_NULLS`, `@DX_DROP_NULLS`, `@DX_UTC`, `@DX_CATEGORIZE`, `@DX_HASH_COLUMNS`, `@DX_CAST_UNIVERSAL`.

Правила:
- Аннотация это строка комментария (`-- @DX_...`, допустим и такой комментарий внутри `/* ... */`). Внутри строковых литералов аннотации не ищутся.
- Значение это остаток строки: для `@DX_OUT` путь может содержать пробелы. Значение с пустым текстом игнорируется с предупреждением (следующая строка запроса не захватывается).
- `@DX_FILL_NULLS` и `@DX_DROP_NULLS` без списка столбцов означают «все столбцы»; со списком принимают его через запятую или пробел (двоеточие после имени необязательно).
- Если одна и та же аннотация указана несколько раз, действует первая.
- Параметры в комментариях переопределяют глобальные параметры (переданные через CLI). Булевы флаги (`@DX_UTC`, `@DX_CAST_UNIVERSAL`) можно только включить. Уровень сжатия из CLI сохраняется, только если аннотация не меняет алгоритм.
- Аннотация, стоящая после `;` в той же строке, относится к **следующему** запросу.

### 3. Автоматическое логирование
Утилита автоматически ведет журнал работы в файле `export_log.txt` (в папке запуска): одна запись на строку. Записывается время старта, длительность, количество выгруженных строк, итоговый размер файла в МБ, начало текста запроса (первые 100 символов, без комментариев) и статус (`SUCCESS`/`ERROR`). Пароли из текста ошибок скрываются. Предупреждения выводятся в stderr и в журнал не попадают.

### 4. Коды возврата
- `0` : все запросы выполнены.
- `1` : ошибка выгрузки или проверки аргументов (в том числе, если упал хотя бы один запрос при `--continue-on-error`).
- `2` : ошибка разбора аргументов командной строки.

### 5. Порядок преобразований
Чтение из БД, затем `--hash-columns`, `--utc`, `--categorize`, `--fill-nulls`, `--drop-nulls`, `--cast-universal`, запись. Файл пишется во временный файл рядом с целевым и переименовывается после успеха: при сбое посреди записи прежняя версия файла не портится.

### 6. Ограничения
- Результат запроса целиком загружается в память (по одному на воркера). Для очень больших таблиц используйте `--partition-on`/`--partitions` и ограничивайте `--workers`.
- Типы, которые connectorx не умеет читать (для Oracle например `BOOLEAN`, `INTERVAL`, `TIMESTAMP WITH LOCAL TIME ZONE`, `ROWID`, `RAW`; для PostgreSQL `interval`, `money`, `xml`), приводят к ошибке запроса (запись `ERROR` в журнале). Приведите такую колонку в самом SQL (например, `CAST(col AS VARCHAR2(100))`).
- Для базы данных, которой нет в таблице выше, используйте DuckDB.

## Примеры использования

**1. Простая выгрузка в Parquet в один поток (запрос текстом):**
```bash
db-extractor --conn "postgresql://user:pass@localhost:5432/mydb" \
             --query "SELECT * FROM public.users WHERE active = true" \
             --out "users.parquet"
```

**2. Выгрузка в CSV с использованием SQL-файла (классический способ):**
```bash
db-extractor --conn "oracle://user:pass@10.0.0.1:1521/ORCL" \
             --query-file "./scripts/complex_report.sql" \
             --out "report.csv"
```

**3. Пакетная выгрузка нескольких таблиц:**
```bash
db-extractor --conn "oracle://user:pass@10.0.0.1:1521/ORCL" \
             --query-file "./scripts/multi_export.sql"
```

**4. Многопоточная выгрузка через CLI (и сжатие ZSTD):**
```bash
db-extractor --conn "postgresql://user:pass@localhost:5432/mydb" \
             --query "SELECT * FROM large_events" \
             --partition-on "event_id" \
             --partitions 10 \
             --compression zstd \
             --out "events.parquet"
```

**5. Строка подключения не в командной строке:**
```bash
export DB_EXTRACTOR_CONN="oracle://user:pass@10.0.0.1:1521/ORCL"
db-extractor --query "SELECT * FROM orders" --out orders.parquet --cast-universal
```

## Разработка

```bash
pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

Тесты на DataFrame и сквозные тесты на SQLite требуют установленных `polars` и `connectorx`; без них такие тесты пропускаются. Изменения описаны в [CHANGELOG.md](CHANGELOG.md).
